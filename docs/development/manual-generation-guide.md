# マニュアルをアプリで見られるようにする手順

Googleドキュメントで書かれたマニュアルを、スマホ向けの解説HTMLに変換し、SeeFTアプリのシフトカードから開けるようにするまでの手順です。

工程は5つ。必要な権限が工程ごとに違うので、分担できます。

```
① Googleドキュメントをダウンロード   ドキュメントの閲覧権限があれば誰でも
② 解説HTMLに変換                   Macのセットアップが要る（初回のみ）
③ 中身を確認                       誰でも
④ サーバーにアップロード             アップロードトークンがあれば誰でも
⑤ タスクに紐づける                  シフトスプシの編集権限があれば誰でも
```

閲覧は技大祭のGoogleアカウント（`〜.nutfes@gmail.com`）を持つ委員全員が可能です。

ダウンロードしたzipは `docs/manuals/_zips/` に置いてください。このディレクトリはgit管理外（`.gitignore`）なので、リポジトリを汚しません。

---

## まとめて実行する（①〜④）

①〜④を1人で担当するなら、通しで実行するスクリプトがあります。

```bash
scripts/automation/run_pipeline.sh docs/manuals/_zips/45th_企画マニュアル_縁日.zip \
  --id en-nichi \
  --doc-url "https://docs.google.com/document/d/xxxx/edit"
```

- ③（見た目・文章の確認）の後に一度だけ確認を挟みます。問題なければ `y` でアップロードへ進みます
- `--prompt` / `--model` で②の設定を変えられます（省略時は `card-strict` / `claude-opus-4-7`）
- `--yes` を付けると確認をすべてスキップします（自動化・CI向け。人手での見た目確認を省略することになるので通常は非推奨）
- ④のトークンは環境変数 `MANUAL_UPLOAD_TOKEN` を設定しておけば対話入力なしで進みます（後述）。未設定なら通常どおり貼り付けを求められます
- ⑤（シフトスプシへの紐付け）はスプシ・GAS側の作業のため対象外です。スクリプトの最後に④の出力（対応表に貼る行）が表示されるので、それを「⑤ タスクに紐づける」の手順1で貼ってください

個別に工程ごと実行したい場合は、以下の①〜⑤をそれぞれ参照してください。

---

## 最初の1回だけ（環境の準備）

②を行う人のみ必要です。③④⑤だけを担当するなら不要です。

```bash
brew install pandoc uv
claude login
git clone https://github.com/NUTFes/SeeFT.git
cd SeeFT
uv sync --project scripts/claude-slide
```

あわせて、アップロード用トークンを上林から受け取ってください。④で使います。

---

## ① Googleドキュメントをダウンロードする

対象のドキュメントを開き、`ファイル > ダウンロード > ウェブページ（.html、zip形式）` を選びます。

**PDFやWordでは画像が取り出せません。必ずzipです。**

ダウンロードしたzipを `docs/manuals/_zips/` に置いてから渡します。

```bash
python3 scripts/automation/prepare_manual.py docs/manuals/_zips/45th_企画マニュアル_縁日.zip
```

`docs/manuals/{マニュアル名}/` に展開されます。マニュアル名はzipのファイル名から決まります。

実行後、表示された名前を確認してください。**この名前がシフトスプシ「タスク一覧」M列の値と一致していないと、⑤で紐付けが失敗します。**

---

## ② 解説HTMLに変換する

```bash
uv run --project scripts/claude-slide python scripts/claude-slide/generate_slide.py \
  --prompt card-strict --model claude-opus-4-7 docs/manuals/45th_企画マニュアル_縁日
```

1本あたり2〜6分かかります。同じディレクトリに `slide_claude.card-strict.html` ができます。

`card-strict` は文章を一字一句変えないプロンプトです。元の文面は部門長と執行部の間で調整済みなので、変換時に文言を動かさないためです。

### Claudeの契約がない場合

変換だけは他のAI（ChatGPT、Codex など）でも行えます。

1. `pandoc -f html -t markdown docs/manuals/{名前}/source.html` でMarkdownにする
2. `.claude/manual-prompt-card-strict.md` の1つ目のコードブロックを指示として渡す
3. 2つ目のブロックに、画像ファイル名の一覧とMarkdownを入れて渡す
4. 返ってきたHTMLを `docs/manuals/{名前}/slide_claude.card-strict.html` として保存
5. 画像を埋め込む（AIのアカウント不要）

```bash
python3 scripts/claude-slide/embed_images.py docs/manuals/45th_企画マニュアル_縁日
```

## ③ 中身を確認する

### 文章が正しく引き継がれたか

```bash
uv run --project scripts/claude-slide python scripts/claude-slide/verify_slide_mechanical.py \
  docs/manuals/45th_企画マニュアル_縁日
```

`文章チェック結果.card-strict.md` が出ます。部門長にそのまま渡せる日本語のレポートです。

見るのは「確認してほしい本文差」だけで構いません。「確認不要の差」は見出し番号やレイアウトの違いで、内容は変わっていません。

差分が多く出るのは、元の文書に大きな表が複数ある場合です。表の行が組み直された結果なので、件数ではなく中身を一目見て判断します。

### 見た目

ブラウザで開いて、スマホ幅（開発者ツールで375px程度）で確認します。

```bash
open docs/manuals/45th_企画マニュアル_縁日/slide_claude.card-strict.html
```

**元の文書の問題もここで見つかります。** 実例として、日時の見出しがキーボードを叩いたような文字列になっていたマニュアルがありました。変換の不具合ではなく元の文書がそうなっていたものです。見つけたら担当の部門に直してもらってください。

## ④ サーバーにアップロードする

```bash
python3 scripts/automation/upload_manual.py \
  --id en-nichi \
  --doc-url "https://docs.google.com/document/d/xxxx/edit" \
  docs/manuals/45th_企画マニュアル_縁日
```

- `-id` は公開URLになる文字列です。半角英数字と  `_` のみ。後から見て何のマニュアルか分かる名前にします（`en-nichi`、`stamp-rally` など）
- `-doc-url` はGoogleドキュメントの共有URLです。⑤で使います

トークンを訊かれるので貼り付けます。画面にも履歴にも残りません。

毎回貼るのが面倒なら、環境変数 `MANUAL_UPLOAD_TOKEN` にあらかじめ設定しておけば、この確認をスキップして自動で読みに行きます。シェルの履歴に平文で残さないよう、`read -rs` で受けてから `export` してください。

```bash
printf 'トークン: '; read -rs MANUAL_UPLOAD_TOKEN; echo; export MANUAL_UPLOAD_TOKEN
```

送信前にHTMLが壊れていないかとサイズを検査するので、不完全なファイルが公開されることはありません。

成功すると、⑤でそのまま貼れる1行が表示されます。

```
成功: https://seeft-api.nutfes.net/manuals/en-nichi

「マニュアルURL」シートに貼る行（タブ区切り）:

45th_企画マニュアル_縁日 https://docs.google.com/document/d/xxxx/edit    https://seeft-api.nutfes.net/manuals/en-nichi
```

## ⑤ タスクに紐づける

シフトスプシ `45th_シフト_ver0` で作業します。触るのは「マニュアルURL」シート1枚だけです。

### 仕組み

```
[マニュアルURL シート]  A=マニュアル名 / B=ドキュメントURL / C=スライドURL
      │ VLOOKUP（タスク一覧M列をキーに引く）
      ▼
[タスク一覧シート]  M列=マニュアル名 → R列・S列が自動で埋まる
      │ SeeFTメニュー > タスク送信
      ▼
[アプリのシフトカードにボタンが出る]
```

**対応表に1行足すと、そのマニュアル名を持つ全タスクに自動で広がります。** 1つのマニュアルに対しタスクは4〜9件あるのが普通で、その分の作業が1行で済みます。

### 手順

1. 「マニュアルURL」シートの空き行のA列に、④で表示された1行を貼る（3列が一度に埋まります）
2. **A列がタスク一覧M列と完全に一致しているか確認する**
3. `SeeFTメニュー > inspectManualUrlLookup` を実行し、対象マニュアルのR列・S列にURLが出ているか確認する
4. `SeeFTメニュー > タスク送信` を実行する
5. アプリのシフトカードにボタンが出れば完了

### B列とC列の違い

| 列 | 入れるもの | アプリのボタン |
| --- | --- | --- |
| B列 | Googleドキュメントの共有URL | ドキュメント版 |
| C列 | ④で発行された `manual_url` | HTML版 |

**B列だけ埋めるのも正常な使い方です。** HTMLを作っていないマニュアルでも、ドキュメント版のボタンは出せます。

## 気をつけること

### A列は手で打たない

VLOOKUPは完全一致です。1文字でも違うと**エラーを出さずにS列が空になり**、ボタンが出ません。

```
45th_企画マニュアル_縁日     ← M列と同じ。引ける
45th_企画マニュアル_縁日␣    ← 末尾に半角スペース。外れる
45th＿企画マニュアル＿縁日    ← アンダースコアが全角。外れる
```

タスク一覧M列のセルをコピーして貼るのが確実です。

### タスク一覧のM列は絶対に編集しない

M列は8つの局のファイルを取り込んで表示しているだけで、**編集するとタスク一覧が全部消えます**（実際に起きています。消えたら `ファイル > 版履歴` から復元してください）。

M列を直したいときは、担当局のタスクファイル側を編集します。

### ドキュメント名を変えると紐付けが切れる

M列の多くはGoogleドキュメントへのリンク（スマートチップ）で、表示されるのは**そのドキュメントの現在の名前**です。ドキュメントをリネームすると、誰もスプシを触っていないのにM列の値が変わり、対応表A列と合わなくなります。

ドキュメント名を変えたら、対応表A列も同じ値に直してください。

逆にこれは便利でもあります。M列の文字が汚れている（末尾スペースなど）ときは、**ドキュメント名を直せば全部まとめて直ります**。スプシ側は触らずに済みます。

### 同じ名前のタスクは最初の1行だけが送られる

タスク一覧には同じタスクが日程分だけ並びます。送信されるのは最初に現れた行だけなので、その行のM列が空だとURLが送られません。M列は同名タスクの全行に入れてください。

### データベースを直接書き換えない

タスク送信は差分更新ではなく全面同期で、スプレッドシートに無い値は消えます。SQLで直接書いた値も、次の送信で上書きされます。入力先は「マニュアルURL」シートに統一してください。

### 生成後にHTMLを手で直しても、作り直すと消えます

恒久的に直したいときは、元のGoogleドキュメントを修正するか、`docs/manuals/{名前}/instructions.md` に指示を書きます。このファイルがあると、次の生成時に「今回の追加・修正指示」として反映されます。

```markdown
-スケジュールはタイムライン形式と表の二重出力にせず、表のみにする
```

## うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| シフトカードにボタンが出ない | タスク一覧S列（HTML版）またはR列（ドキュメント版）が空でないか。空なら対応表A列とM列の文字列が一致しているか |
| S列は埋まっているのにアプリに出ない | タスク送信を実行したか |
| 1タスクにしか反映されない | 他のタスクのM列が空か、別の値になっている。担当局のタスクファイルで確認 |
| マニュアルを開くと403 | 個人のGmailでログインしている。`〜.nutfes@gmail.com` に切り替える |
| マニュアルを開くと404 | アップロード時の `--id` とURLが一致しているか |
| アップロードが401 | トークンが違う。または サーバー側でトークンが未設定 |
| アップロードが403 | APIはこの番号を返しません。ネットワーク側で止められています。上林に連絡 |

## 【参考】APIの仕様

スクリプトが動かないときの切り分けや、curlで直接叩きたいとき用です。

### アップロード

```
PUT https://seeft-api.nutfes.net/manuals/{id}
Authorization: Bearer {トークン}
Content-Type: text/html
（ボディ: HTMLファイルそのもの）
```

| 項目 | 内容 |
| --- | --- |
| `{id}` の規則 | `a-z` `0-9` `_` `-` のみ、1〜64文字 |
| サイズ上限 | 20MB |
| 反映 | 即時。APIの再起動は不要 |

成功すると `201 Created` で次が返ります。

```json
{ "id": "en-nichi", "manual_url": "https://seeft-api.nutfes.net/manuals/en-nichi" }
```

キー名は `url` から `manual_url` に変更しましたが、**本番へ反映されるまでは `url` で返ります**。スクリプトは両方に対応しています。

| ステータス | 意味 |
| --- | --- |
| 401 | トークンが違う、または サーバー側でトークンが未設定（設定漏れで素通りしないよう、未設定でも拒否します） |
| 400 | `{id}` が命名規則に反している |
| 413 | 20MBを超えている |
| 500 | サーバー側の保存失敗 |
| 403 | **APIはこの番号を返しません。** 手前のネットワーク機器が遮断しています |

curlで送る場合は、トークンをコマンドに直接書かないでください。シェルの履歴に平文で残ります。

```bash
printf 'トークン: '; read -rs MANUAL_UPLOAD_TOKEN; echo; export MANUAL_UPLOAD_TOKEN
curl -X PUT "https://seeft-api.nutfes.net/manuals/en-nichi" -H "Authorization: Bearer$MANUAL_UPLOAD_TOKEN" -H "Content-Type: text/html" --data-binary @docs/manuals/45th_企画マニュアル_縁日/slide_claude.card-strict.html
```

### 閲覧

```
GET https://seeft-api.nutfes.net/manuals/{id}
```

技大祭のGoogleアカウントでのログインが必要です。ログイン状態は30日間保持されます。個人のGmailでは403になります。

### タスクへの反映

`SeeFTメニュー > タスク送信` が呼んでいるのはこれです。

```
POST https://seeft-api.nutfes.net/api/update_tasks_and_places
```

タスク一覧の各行から、タスク名・管轄局・集合場所・最大人数・R列（`url`）・S列（`manualUrl`）を送ります。受け取った側はタスク名で既存レコードを探し、`tasks.url` と `tasks.manual_url` を両方とも書き換えます。

`http://` `https://` で始まらない値は空として送られます。「まだ作っていない」などのメモをR列・S列に書いても、リンク切れのボタンが出ることはありません。
