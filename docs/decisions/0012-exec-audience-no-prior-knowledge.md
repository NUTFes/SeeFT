# 0012: 執行部向けの説明は、技術の前提知識がない人向けに組む

- 状態：採用
- 決めた日：2026-05-11
- 決めた人：45th の PM
- 出典：理由の記録は PM の作業メモのみ（公開の出典なし）

## 背景

マニュアルを読みやすい形に変換する仕組みを、執行部に説明するスライドを作った。最初の版には、使う AI サービスの種類や、処理の方式を3つ比べた表など、開発の中で検討したことがそのまま入っていた。

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| 開発で検討したことを、そのまま載せる | 検討の厚さが伝わる | 聞き手が技術の言葉を知らず、何を決めてほしいのかが伝わらない |
| 前提知識がない人向けに、課題と提案と費用に絞る | 聞き手が判断できる | 技術の詳細は別の文書に分ける手間がかかる |

## 決定

執行部など、開発をしていない人向けの説明は、技術の前提知識が全くない人が読んでも分かるように組む。

- 流れは「課題 → やりたいこと → しくみ → メリット → コスト → 日程 → 確かめたいこと」
- 技術用語（API、SDK、コマンド名など）は、本当に要るかを考えてから使う。「AI」「Google ドキュメント」「Web ページ」くらいの一般の言葉までにする
- 方式の比較、内部の設定値、引き継ぎの細かい事項は、説明の資料から外して別の文書にする

## 理由

執行部に説明するのは、判断してもらうため（予算を出すか、運用を変えるか）である。聞き手に分からない言葉が入ると、判断に要る情報まで伝わらなくなる。開発の中の検討は、執行部の関心事ではない。
