# 0009: issue と PR でコードを引用するときは、言語を指定したコードブロックに入れる

- 状態：採用
- 決めた日：不明（2026 年）
- 決めた人：45th の PM
- 出典：理由の記録は PM の作業メモのみ（公開の出典なし）

## 背景

issue や PR の本文で、コードの場所を示すときに、「L123: コード」のような行を箇条書きで並べることがあった。

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| 箇条書きで「L123: コード」と並べる | 書くのが楽 | 行番号・コード・コメント・日本語が混ざって読みにくい |
| 言語を指定したコードブロックに入れる | 等幅の文字と色分けで、一目で読める | コードブロックの書き方を覚える必要がある |

## 決定

issue と PR の本文でコードを引用するときは、` ```go ` や ` ```dart ` のように言語を指定したコードブロックに入れ、上にファイル名を書く。ファイル名と行番号を1つだけ示すときは、インラインのバッククォートで構わない。作業のチェックリスト（`- [ ]`）はこれまでどおりでよい。

## 理由

箇条書きだと、行番号とコードと説明の境目が見えにくい。コードブロックに入れると、GitHub が等幅の文字と色分けで表示するので、どこがコードかがすぐ分かる。
