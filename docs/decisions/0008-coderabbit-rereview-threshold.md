# 0008: 指摘への小さな修正では、CodeRabbit に再レビューを頼まない

- 状態：採用
- 決めた日：2026-09-14
- 決めた人：45th の PM
- 出典：#519

## 背景

本番の静的配信を直す PR（#519）で、CodeRabbit の指摘1件を直した。1つの関数の 15 行ほどの修正で、テストも通っていた。このとき、CodeRabbit のレビューの枠が戻ったら再レビューを頼むかどうかを決める必要があった。

CodeRabbit は無料枠のため、レビューは1時間に1回しかできない。技大祭の直前で、ほかにもレビューを待つ PR があった。

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| 指摘を直したら、毎回再レビューを頼む | 直し方の誤りを機械に拾わせられる | 1時間に1回の枠が、小さな修正の確認に消える。ほかの PR が待たされる |
| 基準を満たすときだけ頼まない | 枠を、まだ見られていない PR に回せる | 基準の判断が要る |
| 再レビューは頼まない | 枠を使わない | 大きく直したときの誤りも拾えない |

## 決定

指摘への修正が次の2つを満たすなら、再レビューを頼まない。

- 直し方が、指摘の提案と同じ筋になっている
- 境目のケースを、テストで確かめてある

直し方が提案から大きく外れたとき、ほかの場所にも手を入れたとき、テストで押さえられていないときは、再レビューを頼む。

## 理由

指摘に沿った修正で、テストもあるなら、CodeRabbit に同じことを確かめさせる価値は小さい。1時間に1回の枠は、まだ誰も見ていない PR のレビューに使った方が価値が高い。

## 前提

- CodeRabbit の無料枠が、1時間に1回のレビューであること
- 決まりの本体は `docs/development/workflow.md` の7節
