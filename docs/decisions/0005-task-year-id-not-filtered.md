# 0005: tasks の seed 由来の行は年度をまたいで使い、名前で引くときに year_id で絞らない

- 状態：採用
- 決めた日：2026-09-16
- 決めた人：45th の PM
- 確信度：高
- 出典：#506、#523

## 背景

GAS からシフトを送ると、同じ名前のタスクが送るたびに増え続ける不具合があった（#506）。45th の本番では、36 分間に同じ名前のタスクが 2,504 行作られていた。

直すときに、issue のチェックリストには「タスクを名前で引くとき（`FindByNames`）に、年度（year_id）で絞る」という案があった。年度で絞れば、前の年度の同じ名前のタスクと混ざらない。

ところが本番の tasks には、`postgresql/db/seed.sql` から入った行が、43 年度のまま 45th の運用データとして使われていた。

```text
id=1  空文字（未割当の印）   year_id=43  45th のシフト 12,289 件が参照
id=2  NG（参加不可の印）     year_id=43  45th のシフト  8,950 件が参照
id=3  タスク外               year_id=43  mobile のレスキュー送信に id が直書き
```

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| 名前で引くときに、今の年度（45）で絞る | 年度ごとのタスクが混ざらない | id 1〜3 を見失う。GAS の送信が 45 年度版の「空文字」や「NG」を新しく作り、既存の2万件のシフトが古い行を指したまま取り残される |
| 先に本番の id 1〜3 の year_id を今の年度にそろえてから、年度で絞る | 年度で絞れる | 本番データの書き換えが要る。mobile の直書きや、年度が変わるたびにそろえ直す作業も要る |
| 年度で絞らず、同じ名前が複数あるときは id の一番小さい（古い）行を使う | 本番データを変えずに直せる。seed 由来の行はずっと同じ id で使える | 前の年度に同じ名前のタスクがあると、それに紐づく |

## 決定

tasks の seed 由来の行（空文字・NG・タスク外）は、年度をまたいで同じ行を使う。タスクを名前で引くときは year_id で絞らず、同じ名前が複数あるときは id の一番小さい行を使う（#523）。

理由は `FindByNames` のコメントにも書いてある。

## 理由

年度で絞ると、本番で2万件のシフトが参照している id 1〜2 と、mobile が直書きで送る id 3 を見失うからである。本番データを書き換えずに増え続ける不具合を止めるには、絞らない方が安全だった。

seed.sql は、DB を作り直しても、この3行を 43 年度で入れる。年度が変わっても、この3行は同じ id と同じ year_id のまま残る。

## 前提

- 名前で引く処理：`api/lib/internals/repository/task_repository.go#taskRepository.FindByNames`
- シフトの送信：`api/lib/usecase/shift_usecase.go#shiftUseCase.UpdateShiftsFromGAS`、名前の正規化は `api/lib/usecase/shift_usecase.go#normalizeTaskName`
- seed の3行：`postgresql/db/seed.sql`
- レスキューの「タスク外」を id 3 で送る mobile：`mobile/lib/pages/rescue/rescue_request_tab/tab_pages/trouble.dart`
- **年度で絞りたくなったら**、先に id 1〜3 の扱い（year_id をそろえるか、年度に関係なく引く特別扱いにするか）を決め、mobile の直書きも直す。そのときは新しい ADR を書く

## 結果

#523 のマージ後、同じ名前のタスクが増え続ける不具合は止まった。
