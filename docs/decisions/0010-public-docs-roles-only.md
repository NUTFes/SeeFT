# 0010: 公開の文書には個人名を書かず役職で書き、委員会の中の言葉の意味も書かない

- 状態：採用
- 決めた日：2026-09-28
- 決めた人：45th の PM
- 出典：#559、#560

## 背景

45th の運営の実態を調べた結果を、`docs/operations/` に反映することになった（#559）。調べた資料には、誰がどのファイルを持っているか、誰が何を決めたかが、実名で書いてあった。シフト表で使われている、委員会の中だけで通じる言葉の意味も書いてあった。

SeeFT のリポジトリは公開されている。

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| 実名と言葉の意味をそのまま書く | 誰に聞けばよいかがすぐ分かる | 学生の名前と役割が、誰でも読める場所に残り続ける。内輪の言葉が外に出る |
| 公開の文書は役職だけにし、名前と言葉の意味は非公開の資料に分ける | 公開の範囲を必要なだけに絞れる | 誰に聞くかを知るには、非公開の資料も読む必要がある |

## 決定

公開の文書（`docs/`・issue・PR の本文・ADR）には、個人名を書かず、役職（「45th の PM」「執行部」など）で書く。委員会の中だけで通じる言葉の意味も書かない。例に出すなら一般的な言葉だけにする。名前・ファイルの ID・持ち主のアカウント・言葉の意味は、非公開の資料に置く。

## 理由

公開リポジトリに書いたものは、消しても履歴に残る。役職で書けば、文書の役目（誰の役割が何か）は果たせる。個人を特定する情報は、引き継ぎに要る人だけが読める非公開の資料で十分に渡せる。

## 前提

- リポジトリが公開されていること
- 同じ決まりが `AGENTS.md` の ADR の節と `docs/decisions/README.md` にもある

## 結果

`docs/operations/` の運営の記述は、役職だけで書き直してマージした（#560）。
