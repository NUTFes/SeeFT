# 0014: 本番で打つコマンドは、打つ場所を見出しで分けて書く

- 状態：採用
- 決めた日：2026-09-13
- 決めた人：45th の PM
- 出典：理由の記録は PM の作業メモのみ（公開の出典なし）

## 背景

本番の DB につながるサーバーのコンソールで作業するときに、psql（DB に命令を送る道具）の中にいるのに、シェル（サーバーの OS）のコマンドを打ってしまうことが2回あった（2026-08-28 と 2026-09-13）。2回目は、案内の文が「サーバーのコンソールで次を打つ」と「psql の中で次を打つ」を続けて書いていて、どちらの状態で打つのかが曖昧だった。psql は、文の終わりが来るまで入力を待ち続けるので、打ったコマンドは実行されずに止まった。

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| コマンドの前にプロンプトの記号（`$` や `=>`）を付ける | どこで打つかが1行で分かる | コピーすると記号も一緒に貼られ、コマンドが壊れる |
| 打つ場所ごとに見出しを分ける | コピーしてもコマンドが壊れない | 見出しの分だけ文書が長くなる |

## 決定

本番で打つコマンドを案内するときは、打つ場所ごとに見出しを分ける。見出しには、その場所で画面に出ている表示を書く（例：「シェル（`root@...#` と出ている状態）で」「psql の中（`seeft_db=>` と出ている状態）で」）。

psql の中にいる状態からシェルのコマンドを案内するときは、先頭に `\q`（psql を抜ける）を書く。

## 理由

本番の作業は、打ち間違えると取り返しがつかないことがある。コマンドはコピーして貼ることが多いので、記号をコマンドに付けるやり方は使えない。場所を見出しに出せば、コピーする部分を壊さずに、どこで打つかを伝えられる。
