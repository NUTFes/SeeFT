# 0007: PR を出す前の点検は差分全体にかけ、直したことはほかの場所にも広げる

- 状態：採用
- 決めた日：2026-09-29
- 決めた人：45th の PM
- 出典：#564

## 背景

新しく入った人向けの資料を足した PR（#564）で、PR を出す前の点検を、主な成果物（`docs/development/onboarding.md`）にだけかけた。同じ PR で、ついでに README など3つの文書も直していたが、そちらは点検しなかった。

CodeRabbit が指摘して、まだ直していなかった3件は、すべてその点検しなかったファイルにあった。

- 主な成果物で直した内容（CORS で許可しているのはポート 45029 だけ、など）を、同じ PR のほかの文書に広げていなかった
- テストの件数を、同じファイルを2回数えるやり方で数えて、18 件を 24 件と書いていた
- 別の節では正しく書いていた条件を、1行の要約で落としていた

## 候補

| 候補 | 良い点 | 悪い点 |
| --- | --- | --- |
| 主な成果物だけを点検し、残りは CodeRabbit に任せる | 早い | CodeRabbit の枠は1時間に1回しかなく、指摘が出るまで誤りが残る |
| PR の差分全体を点検し、直した主張は `git grep` でほかの場所も探す | 自分で見つけられる | 点検に時間がかかる |

## 決定

PR を出す前の点検は、PR の差分全体にかける。1か所を直したら、同じ主張を `git grep` で全体から探して、ほかの場所も直す。件数は、重複しない方法（`git ls-files '<パターン>' | wc -l` など）で数え、書いた数字を元のデータと突き合わせる。

## 理由

元の情報を正しく読めていても、要約する、数える、条件を省く、という作業の途中で誤りが入る。点検の範囲を絞ると、その範囲の外で入った誤りは、レビューで指摘されるまで残る。
