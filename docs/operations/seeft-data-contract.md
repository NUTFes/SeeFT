# SeeFT に渡すデータの約束事

スプレッドシートの作りは毎年変わってよい。変えてはいけないのは、SeeFT の API が受け取るデータの形である。この文書はその約束事をまとめる。46th でスプレッドシートを作り直すときは、ここに書いた形でデータを送れるかを確かめればよい。

スプレッドシート側の構成は [スプレッドシートの依存関係](spreadsheet-map.md) にある。記述は 2026-09-21 時点の develop（API・GAS）と、45th の本番での実測に基づく。

## 送る順番

**名簿 → タスク → シフト** の順に送る。この順番には2つの理由がある。

1. シフトは、ユーザー名とタスク名の完全一致で名簿とタスクに結びつく。先にシフトを送ると、名前が見つからずにエラーになるか、タスクが勝手に作られる。
2. タスク名に全角スペースが入っていると、シフト送信が同じ名前のタスクを送信のたびに作り直してしまう（issue #506）。タスク送信を先に済ませておけば、半角にそろえた名前が先に登録されるので起きない。45th では順番が逆になった1回で、同じ名前のタスクが2,504行できた。

3つとも、シフトスプシの SeeFT メニューから GAS で送る。送り先はスクリプトプロパティ `API_BASE_URL` で決まる（本番は `https://seeft-api.nutfes.net`、末尾のスラッシュは付けない）。検証環境に向けたまま本番の作業をしないよう、送る前にこの値を確認する。

## 名簿（`POST /api/update_users`）

送信元は、日程シート `準々備日` の3〜5行目（名前・局・学年）と、名簿作成アンケートの回答（名前で照合）である。

| 項目 | 中身 | 約束事 |
| --- | --- | --- |
| `name` | 名前 | **日程シートの表記のまま送る**。シフト送信と一字一句そろっている必要がある。API は名前をキーにして、既存のユーザーを上書きする |
| `bureau` | 局 | `執行部` `執行部補佐` `総務局` `企画局` `渉外局` `財務局` `制作局` `情報局` `産学局` のどれか。兼務は「企画局, 財務局」のように書かれるので、先頭を主務として送る |
| `grade` | 学年 | `B1`〜`B4`、`M1`、`M2`、`D1`〜`D3`、`OB` |
| `studentNumber` | 学籍番号 | **8桁**。ログインの ID になる。欠けていると誰もログインできない |
| `tel` | 電話番号 | 数字だけにして送る。レスキューのスプシに載り、対応者が折り返しに使う |
| `mail` | 技大祭メール | Slack ID を引くキーになる。空で送ると既存の値を残す |
| `slackUserID` | Slack のユーザーID | GAS が Slack の `users.lookupByEmail` で引く。空で送ると既存の値を残す |
| `department` | 課程 | 45th は `未所属` 固定で送った。アンケートの書き方（「電気」「物生」など）が API の変換表と合わないため。どこからも使われていない |

初期パスワードは、API の環境変数 `USER_DEFAULT_PASSWORD` で決まる。ユーザーが作られた時点の値が焼き込まれるので、DB を作り直す前に設定しておく。

## タスク（`POST /api/update_tasks_and_places`）

送信元は、シフトスプシの `タスク一覧` の4行目以降である。

| 項目 | 列 | 約束事 |
| --- | --- | --- |
| `taskName` | A | 全角スペースは半角にそろえて送る。**同じ名前が複数行あると、先頭の行だけが使われる** |
| `bureau` | F | 管轄局 |
| `place` | H | 集合場所。**空だと「本部」になる**。知らない名前なら、集合場所が新しく作られる |
| `maxMember` | L | 最大人数。数字でなければ1 |
| `url` | R | ドキュメント版マニュアル（45th の後半は PDF）。`http(s)://` で始まらない値は空にして送る |
| `manualUrl` | S | HTML 版マニュアル。`url` と同じ扱い |
| `yearID` | — | スクリプトプロパティ `YEAR_ID`（未設定なら45） |

- タスク名をキーにして上書きする。**タスク送信は削除をしない。** 一度送ったタスクは、スプシから消しても DB に残る。45th では、参加不可の申告がタスクファイルに紛れ込み、「ゼミ」というタスクが本番に入った。
- `url` と `manualUrl` は送信のたびに両方とも上書きされる。**DB を SQL で直接書き換えても、次のタスク送信で消える。** マニュアルの紐付けは、シフトスプシの `マニュアルURL` シートだけで行う。
- 同じ名前が先勝ちになるので、日によって中身が違うタスクは名前を分ける（開店・閉店チェックの件。[事故の記録](incidents-45th.md)）。

## シフト（`POST /api/update_shifts`）

送信元は、日程シートの11行目から下のグリッドである。1セルが1件になる。

| 項目 | 中身 | 約束事 |
| --- | --- | --- |
| `userName` | 3行目の名前 | 名簿の `name` と完全一致（スペースの全角・半角の違いだけは吸収する）。**1人でも見つからないと、その回に送った1,000件のかたまりがエラーになる** |
| `taskName` | セルの値 | タスク名と完全一致。**見つからないと、既定値（管轄局=執行部、最大1人、色なし）でタスクが新しく作られる**。表記ゆれがそのまま別タスクになる |
| `timeID` | A列の時刻 | 0:00 を1とし、15分ごとに1ずつ増える（6:00 は25） |
| `date` | シート名 | `準備日`=1、`1日目`=2、`2日目`=3、`片付け日`=4、`準々備日`=5。**API のコードに固定で書かれている** |
| `weather` | シート名 | `晴れ`=1、`雨`=2 |
| `yearID` | — | スクリプトプロパティ `YEAR_ID` |

セルの値の意味は次のとおり。

- **背景が黒（`#000000`）**：`NG`（参加不可）として送る。アプリには表示されない。
- **空欄**：空文字として送る。アプリでは「割り当てなし」になる。API には行を削除する操作がないので、割り当てを外すときは空欄のまま送り直す。
- **`休憩`**：そのまま送る。アプリでは休憩カードとして表示される（#492）。
- **`飛翔` `研究` `海外` など**：タスクとして作られ、本人のシフトカードに出る。45th では執行部と相談のうえ、そのまま送った。

送信の性質として、次の点を知っておく。

- 1件ずつ DB に書き込む。GAS には6分の実行制限があるので、260秒で自分から打ち切り、次の実行で続きから送る（再開位置はスクリプトプロパティ `SHIFT_RESUME` に残る。最初から送り直すときは「【リセット】最初から送り直す」）。
- **GAS が途中で止まっても、DB には途中まで入っている。** 送信が終わらないように見えても、連打しない。GAS が打ち切られても API は処理を続けているので、次の実行を重ねると同じ行を奪い合って、さらに遅くなる。数分空けてから、DB の件数を先に確かめる。
- シフトの**変更**（タスクが変わったとき）と**新規作成**は `action_logs` に記録され、Slack ID が登録されている人には5分おきに DM で届く。一括で空欄にするような編集をして送ると、数百人に通知が飛ぶ。
- 「送信が完了しました」は、DB がシートと同じであることの証明にならない。送信後にシートを編集すれば、DB は古いままである。

### 送る前に確認するメニュー

シフトスプシの SeeFT メニューに、送信前の確認が用意されている。どれも DB には書き込まない。

| メニュー | 確かめること |
| --- | --- |
| 【事前確認】名前がDBに全部あるか調べる | 日程シートの名前が、すべて名簿として送られているか |
| 【事前確認】タスク名がDBに全部あるか調べる | 日程シートのタスク名が、すべてタスクとして送られているか（ないものは送信時に勝手に作られる） |
| 【事前確認】マニュアルURLの紐付けを点検する | タスク一覧の M 列とマニュアルURLシートの A 列が一致しているか |
| 【調査】送信せず件数だけ数える | そのシートを送ると何件になるか |

## レスキュー

向きが2つある。

**アプリ → スプシ（API が GAS のウェブアプリへ転記する）**

API は環境変数 `RESCUE_GAS_URL`（ウェブアプリの URL）へ JSON を送り、GAS がシートに1行を足す。**URL を知っていれば誰でもスプシに書き込めるので、秘密として扱う。** リポジトリには入れず、サーバーの環境変数にだけ置く。

| `rescue_type` | 書き込むシート | 列の並び |
| --- | --- | --- |
| `question` | 質問 | 対応番号、送信者名、学籍番号、電話番号、学年、局、送信時刻、質問 |
| `trouble` | トラブル | 対応番号、送信者名、学籍番号、電話番号、学年、局、送信時刻、発生場所、タスク名、詳細 |
| `shorthanded` | 人が来ない | 対応番号、送信者名、学籍番号、電話番号、学年、局、送信時刻、場所、タスク名、足りない人数 |

- 対応番号は DB の ID である。スプシ側で書き換えると、返答が別のレスキューに戻ってしまう。
- 電話番号は、先頭の `0` が落ちないようにテキストとして書き込む。
- 同じ人・同じ種類・同じ内容の送信は、180秒のあいだ1件として扱う。押し直した分はスプシに足さず、DB 側で「対応番号Xにまとめました」として閉じる。

**スプシ → アプリ（`onChange` が API へ戻す）**

対応者が対応状況と返答を書くと、`PUT /{question|trouble|shorthanded}-rescues/{対応番号}` が送られる。質問は I・J 列、トラブルと人が来ないは K・L 列を読む。

## 年度が変わるときに直すところ

45th の値がコードと初期データに直接書かれている。46th で DB を作り直す前に、次を確認する。

| 場所 | 45th の状態 | 46th でやること |
| --- | --- | --- |
| `postgresql/db/seed.sql` の `years` と `dates` | `years` に45（2026）、`dates` の id 1〜5 に 45th の日付（2026/09/17〜21） | 46th の年度と日付に書き換える。`dates` の id と日程名の並びは API の固定値と合わせる |
| `api/lib/usecase/shift_usecase.go` の日程名の変換 | `準々備日` は `yearID=45` のときだけ受け付ける | 46th でも準々備日を使うなら直す |
| シフトスプシのスクリプトプロパティ `YEAR_ID` | 未設定なら45 | 46 を設定する |
| `mobile/lib/pages/my_shift_page.dart` | 表示する日程は1〜4で固定、天気は晴れで固定 | 準々備日や雨の日を見せるなら直す |
| `tasks` の id 1〜6 | 初期データの `year_id=43` のまま、45th でも使っている。id 1 の空文字は「割り当てなし」、id 2 の `NG` は「参加不可」、id 3 の `タスク外` はアプリのコードに id が直接書かれている | 消さない。タスクを `year_id` で絞り込む変更を入れると、この3行を見失う |
| `shifts` のインデックス | 本番に手で貼った（issue #500）。migration に入っていないので、DB を作り直すと消える | 作り直したら貼り直すか、#500 を先に片付ける |

**DB を作り直すか、45th のデータを残すか**は 46th で決めることである。`dates` の id 1〜4 は年度をまたいで使い回す作りになっているので、残す場合は年度の混ざり方を先に設計する必要がある。45th は技大祭の前に DB を初期化した。

## Slack 通知を有効にする順番

`SLACK_BOT_TOKEN` を入れる順番を間違えると、それまでに溜まったシフト変更の記録が一斉に DM で飛ぶ。

1. シフト送信を終える（過去分の記録が溜まった状態）
2. API の環境変数に `SLACK_BOT_TOKEN` を入れて起動し直す。この時点では誰の Slack ID も入っていないので、溜まった記録は「送らずに既読」になる
3. シフトスプシのスクリプトプロパティに `SLACK_BOT_TOKEN` を入れ、「1. 名簿を送信」で Slack ID を埋める
4. 以後のシフト変更だけが DM になる

詳しくは [gas/README.md](../../gas/README.md) の「名簿送信と Slack ID の紐付け」にある。
