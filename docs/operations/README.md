# 技大祭の運用記録

SeeFT を使った技大祭の運用を、翌年の担当者が最低限同じように回せるよう記録したものである。45th（2026年）の実績から書いている。

コードはこのリポジトリの develop を使えばよい。一方、シフト・タスク・名簿のスプレッドシートと、それに紐づく Apps Script（GAS）は毎年作り直すことになる。作り直すときに必要な「何をどの順で作り、SeeFT に何を渡し、どこで人の手が要ったか」を、ここに残す。

## ここに書かないもの

このリポジトリは公開されている。次のものは書かず、技大祭の共有ドライブに置く別紙にまとめる。

- スプレッドシート・フォルダ・スクリプトの ID と、所有者・共有範囲
- アカウント名、個人名
- トークンやウェブアプリの URL などの秘密（別紙にも値は書かず、どこに入っているかだけを書く）
- セキュリティ上の問題（非公開のセキュリティアドバイザリで扱う）

## 技大祭が終わったらすぐやること

時間が経つほど記憶が抜け、持ち主が卒業してファイルが消える危険が増える。片付け日から数週間のうちに済ませる。

- [ ] 使ったファイルの**所有者**を確認する。個人のマイドライブにあるものや、卒業・退会で消えるアカウントが持っているものは、技大祭の共有ドライブへ移す
- [ ] ライブの GAS を `clasp clone` し、`gas/` との差分を取る。ずれていればリポジトリに取り込む（シフト・マニュアル割り当て・レスキューの3つ）
- [ ] 本番の DB から、翌年に残すデータ（タスク、アプリ内レビューなど）を取り出す。個人情報の欄は落としてから保存する
- [ ] 本番サーバーの `manuals/`（解説 HTML の置き場）を控えておく。git の管理外で、サーバーを作り直すと消える
- [ ] トークンやウェブアプリの URL がどこに入っていて、誰が持っているかを別紙に書く
- [ ] この文書群の「要確認」と、所要時間の空欄を埋める
- [ ] 後任が一度この文書群どおりに通して、詰まったところに印を付ける。**書いた本人が読み返しても、抜けている前提には気づけない**

## まだ書いていないもの

- 既存機能の改善点（事故の記録と、アプリ内レビュー・執行部アンケートの結果から）
- マニュアルやシフトを作る現場への関わり方（誰が何を決めるか、何を測るか）

## 更新の仕方

翌年が終わったら、年度の数字を書き換えるのではなく、`incidents-46th.md` のように年度ごとの記録を足す。スプレッドシートの構成や約束事が変わった場合は、該当する文書を直し、何年度から変わったかを書く。
