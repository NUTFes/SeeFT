## UIパターン一覧

### card-gallery-horizontal（横スワイプカード）
- いつ使う: 各要素が独立していて、ユーザーが眺めて選ぶ場面
- 要素数: 3〜7枚が理想
- 例: 緊急連絡先、メンバー紹介、当日のイベント一覧
- 実装: flex + overflow-x: auto + scroll-snap-type: x mandatory
- カード幅: 280〜320px固定、ビューポート内に約1.2枚見える

### step-sequence（縦ステップ）
- いつ使う: 順序が重要な作業手順
- 例: 設営手順、撤去手順、トラブル対応フロー
- 実装: 番号付きカード縦並び、各ステップに見出し+説明+画像
- 画像があるステップは画像を直後に配置

### table-with-toggle（折りたたみテーブル）
- いつ使う: 密度の高い表データ、要素数が多い、検索性が必要
- 例: 物品リスト、シフト表
- 実装: details要素 + table、カテゴリごとに折りたためる

### contact-list（アクション可能カード）
- いつ使う: 電話番号やURLを含む、即アクションが要る情報
- 例: 緊急連絡先、各局窓口
- 実装: 各連絡先を独立カード、電話番号は <a href="tel:..."> で発信可能、URLは <a href="..."> でリンク化

### timeline-vertical（縦タイムライン）
- いつ使う: 時系列で並ぶイベント
- 例: 当日タイムテーブル、設営スケジュール
- 実装: 縦線 + 時刻ラベル + イベント説明

### prose-with-cards（散文+補足カード）
- いつ使う: 説明文がメインで、補足情報をハイライトしたい
- 例: 設営概要、前提知識
- 実装: 通常の段落 + 重要情報を枠付きカードで強調

### photo-with-caption（写真+キャプション）
- いつ使う: 視覚情報が主体（地図、完成図、配置図）
- 例: 校舎マップ、本部設営完成図
- 実装: 画像 + ライトボックス（タップで全画面拡大）+ キャプション

## 選択ルール

各セクションに対して、以下の順で判断してください:

1. 電話番号やtelリンクが含まれているか?
   → YES なら contact-list
2. 「手順」「ステップ」「順序」を示す番号付きリストか?
   → YES なら step-sequence
3. 時刻が並んでいるか?
   → YES なら timeline-vertical
4. 表形式のデータで行数が10以上か?
   → YES なら table-with-toggle
5. 独立した3〜7個のアイテム(人物・団体・連絡先)か?
   → YES なら card-gallery-horizontal
6. 主要素が画像(マップ、写真)か?
   → YES なら photo-with-caption
7. 上記以外
   → prose-with-cards

## 厳守事項

- 1ファイル内で複数のUIパターンを混在させてOK(推奨)
- 元Markdownにない情報は絶対に追加しない
- 電話番号は必ず <a href="tel:..."> でラップ
- URLは必ず <a href="..."> でラップ
- 画像は <img onclick="openLightbox(this)"> でライトボックス対応
- 横スワイプUIには下にドットインジケータを必須で付ける
- スマホ縦持ち(380px幅)を最優先、文字サイズ最小15px
